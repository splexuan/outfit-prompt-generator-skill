# 输出结构规范

本文件规定面向用户的提示词呈现方式。目标是让用户能快速比较、看懂设计、复制单套方案并继续修改，同时避免为了结构化而重复相同内容。

## 基本原则

- 默认使用 Markdown，不输出 JSON；用户明确要求程序调用、JSON、YAML 或纯表格时再切换格式。
- 多方案使用“一张总览表＋若干统一方案卡＋一行后续操作”。不要给每套方案再做一张宽表。
- 总览表只负责横向比较，单元格使用短语，不放长句。
- 方案卡中的带标签文本就是完整提示词，不再额外重复一遍“设计拆解”。
- 所有方案使用相同字段顺序；专业维度名称随品类变化，但位置固定。
- 每套必须脱离总览表独立复制，不能使用“同上、同款、延续前述”等上下文依赖表达。
- 反向约束放在各自方案的复制区内，不用批次末尾的共用反向提示代替。

## 七个输出维度

每套方案按以下顺序输出：

1. **核心卖点**：一句话说明最值得记住的设计价值，必须具体，不只写“高级、时尚、爆款”。
2. **款式廓形**：品类、件数、长度、松量、腰线、肩线及整体比例。
3. **结构细节**：领口、袖型、开合、拼片、口袋、绑带、衬里、包边和关键连接关系。
4. **配色图案**：主色、辅色、点缀色的落位，以及图案尺度、方向和疏密。
5. **面料质感**：主辅面料、厚薄、垂坠、弹力、透明度、纹理和光泽行为。
6. **专业维度**：选择与品类最相关的功能维度，不输出空泛的固定字段。
7. **展示构图**：无人物、无衣架的陈列方式、背景、光线、视角、主体间距和完整性。

最后添加 **反向约束**，只列该方案最可能出现的结构、材质和构图错误。

## 动态专业维度

| 品类 | 字段名称 | 应说明的内容 |
|---|---|---|
| 泳装、内衣 | 覆盖与支撑 | 覆盖度、罩杯或胸部支撑、肩带与下围受力、裆部和腿口容量 |
| 运动服 | 运动功能 | 运动类型、活动强度、排汗、弹力、接缝和关节活动量 |
| 户外服 | 防护性能 | 温度、天气、防风防水、透气、保温层次和调节结构 |
| 外套 | 穿着层次 | 内搭容量、保暖等级、开合、防风部位与叠穿关系 |
| 西装、通勤装 | 正式程度 | 场合、肩部结构、驳领、裤褶、面料正式度和内搭关系 |
| 礼服、婚纱 | 礼仪等级 | 场合正式度、裙撑或垂坠、拖尾、内层支撑与行动便利性 |
| 传统服饰 | 形制与文化 | 文化来源、时代、成套部件、穿着层次、系结和纹样位置 |
| 家居服、睡衣 | 舒适性能 | 亲肤、松量、接缝、开合、保暖或透气需求 |
| 日常单品 | 穿着体验 | 活动量、口袋、开合、内搭、季节和易搭配性 |
| 完整穿搭 | 搭配层次 | 内外层顺序、上下装比例、鞋包配饰关系和视觉重心 |

同一套涉及多个类别时，只选择决定设计的一个主专业维度；其他功能写入结构或面料字段，不增加更多栏目。

## 单方案与详细版

- 只有一套时省略方案总览，直接输出方案卡。
- 默认精简完整版中，每个字段通常为一句；详细版可将关键字段扩展到一至三句。
- 用户只要“提示词，不要解释”时，省略总览、卖点引用和操作入口，只输出带字段标签的可复制提示词。
- 用户要求纯自然段时，保留信息顺序但移除字段标签，仍确保提示词独立完整。

## 图片反推格式

图片反推通常只有一套，不使用方案总览：

```text
## 识别概览

一句话概括图中有视觉依据的服装组合、配色和风格。

## 穿搭拆解

- 单品层次：按真实穿着顺序列出可见服装、鞋包与少量配饰。
- 轮廓比例：说明长度、松量、腰线和上下装关系。
- 配色图案：说明可见主辅色、图案与落位。
- 面料质感：只写能从图中合理判断的观感，不断言不可见成分。
- 不确定项：仅在关键结构被遮挡或模糊时出现。

## 可复制提示词

【主体组合】……
【款式廓形】……
【结构层次】……
【配色图案】……
【面料质感】……
【陈列构图】无人物、无衣架……
【反向约束】……
```

不要把人物外貌、身份或身材评价混入穿搭拆解。

## 可读性检查

输出前确认：

- 总览表能否在不读正文时区分各套方案；
- 各方案字段顺序是否一致；
- 动态字段是否真正对应品类；
- 每个字段是否有新信息，没有换词重复；
- 核心卖点是否能在十几秒内被理解；
- 单独复制任一方案后，主体、结构、材质、展示和反向约束是否完整；
- Markdown 表格、标题和空行是否能正常渲染。
