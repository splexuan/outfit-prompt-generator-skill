# 输出结构规范

本文件规定面向用户的提示词呈现方式。目标是让用户能快速比较、看懂设计、复制单套方案并继续修改，同时避免为了结构化而重复相同内容。

## 基本原则

- 默认使用 Markdown，不输出 JSON；用户明确要求程序调用、JSON、YAML 或纯表格时再切换格式。
- 多方案使用“一张总览表＋若干统一方案卡＋一行后续操作”。不要给每套方案再做一张宽表。
- 总览表只负责横向比较，单元格使用短语，不放长句。
- 方案卡中的带标签文本就是完整提示词，不再额外重复一遍“设计拆解”。
- 所有方案使用相同字段顺序；专业维度名称随品类变化，但位置固定。
- 每套必须脱离总览表独立复制，不能使用“同上、同款、延续前述”等上下文依赖表达。
- 反向约束放在各自方案的复制区内，不用批次末尾的共用反向提示代替。

## 九个输出维度

每套方案按以下顺序输出：

1. **核心卖点**：一句话说明最值得记住的设计价值，必须具体，不只写“高级、时尚、爆款”。
2. **创意概念**：说明具体幻想世界、成年少女感的造型语法、形态语言、主创意引擎和区别于常规款的创新；用户明确排除幻想或少女感时按其要求收束。
3. **款式廓形**：品类、件数、长度、松量、腰线、肩线及整体比例。
4. **结构细节**：领口、袖型、开合、拼片、口袋、绑带、衬里、包边和关键连接关系。
5. **配色图案**：主色、辅色、点缀色的落位，以及图案尺度、方向和疏密。
6. **面料质感**：主辅面料、厚薄、垂坠、弹力、透明度、纹理和光泽行为。
7. **专业维度**：选择与品类最相关的功能维度，不输出空泛的固定字段。
8. **镜头动态**：说明身体线条重点、穿着后舞蹈或走秀时动态部件的轨迹，以及后续人物视频最适合的动作或机位。默认单一服装展示中不得要求同时出现正面、侧面和背面，也不得暗示多镜头拼图；静态、日常或实用任务可压缩为一句。
9. **展示构图**：未指定时必须写成一个居中的完整正面单一视图，采用无人物、无衣架且保持自然穿着容量的白色或浅色无缝摄影棚展示，写明柔和漫射光、自然软阴影和完整性；黑底、多角度、分栏和拼图只在用户明确要求时使用，成年人物上身任务改写为相应人物场景。

最后添加 **反向约束**，只列该方案最可能出现的结构、材质和构图错误。

## 动态专业维度

| 品类 | 字段名称 | 应说明的内容 |
|---|---|---|
| 泳装、内衣 | 覆盖与支撑 | 覆盖度、罩杯或胸部支撑、肩带与下围受力、裆部和腿口容量 |
| 运动服 | 运动功能 | 运动类型、活动强度、排汗、弹力、接缝和关节活动量 |
| 户外服 | 防护性能 | 温度、天气、防风防水、透气、保温层次和调节结构 |
| 外套 | 穿着层次 | 内搭容量、保暖等级、开合、防风部位与叠穿关系 |
| 西装、通勤装 | 正式程度 | 场合、肩部结构、驳领、裤褶、面料正式度和内搭关系 |
| 礼服、婚纱 | 礼仪等级 | 场合正式度、裙撑或垂坠、拖尾、内层支撑与行动便利性 |
| 传统服饰 | 形制与文化 | 文化来源、时代、成套部件、穿着层次、系结和纹样位置 |
| 家居服、睡衣 | 舒适性能 | 亲肤、松量、接缝、开合、保暖或透气需求 |
| 日常单品 | 穿着体验 | 活动量、口袋、开合、内搭、季节和易搭配性 |
| 完整穿搭 | 搭配层次 | 内外层顺序、上下装比例、鞋包配饰关系和视觉重心 |

同一套涉及多个类别时，只选择决定设计的一个主专业维度；其他功能写入结构或面料字段，不增加更多栏目。

## 1｜方案名称

> 核心卖点：一句具体且可感知的设计价值。

### 可复制提示词

【创意概念】……
【款式廓形】……
【结构细节】……
【配色图案】……
【面料质感】……
【覆盖与支撑／运动功能／其他动态字段】……

【反向约束】……

渲染环境支持代码块复制按钮时，可把“可复制提示词”放入 `text` 代码块；不支持时保持普通分段文本。无论哪种形式，都不要在字段之间插入解释性旁白。

## 单方案与详细版

- 只有一套时省略方案总览，直接输出方案卡。
- 默认精简完整版中，每个字段通常为一句；详细版可将关键字段扩展到一至三句。
- 用户只要“提示词，不要解释”时，省略总览、卖点引用和操作入口，只输出带字段标签的可复制提示词。
- 用户要求纯自然段时，保留信息顺序但移除字段标签，仍确保提示词独立完整。

## 默认单一视图

用户没有明确写“双视图、二视图、三视图、多角度、拼图、对比板”时，每套方案的 `【展示构图】` 必须明确写入：

```text
一张单一视图服装展示图，画面中只有同一件或同一套服装的一个完整正面主体，居中、同一尺度，白色、米白或珍珠浅灰无缝摄影棚背景，柔和漫射光与自然软阴影，无人物、无衣架，四周留白，完整不裁边；禁止分栏、拼图、画中画、重复服装、第二个主体、侧面视图、背面视图、三视图和局部细节插图。
```

- 默认 3 套表示回复中提供 3 个独立方案和 3 段独立提示词，不表示把三件服装放进一张三栏画面。
- `【镜头动态】` 只描述未来上身拍摄时的动作表现；必须补充“本次成图仍为单一正面视图”，不能让侧转、回眸或背部卖点变成额外展示视图。
- 即使提示词详细描述了背部结构，本次画面也不额外显示背面；用户可继续要求把选中方案扩成双视图。
- 单一视图反向约束至少包含：多角度、多视图、三栏、三视图、正侧背并列、重复主体、拼贴、画中画、局部放大框。

## 双视图与二视图

用户说“双视图”“二视图”或“正背双视图”时，把它视为最终出图画布的硬性构图要求，而不是把回复正文拆成两个 Markdown 栏目。每套方案的 `【展示构图】` 必须明确写入：

```text
一张横向双视图服装设计展示板，画面明确分为左右两栏，左栏完整展示服装正面，右栏完整展示同一服装背面；两栏等宽、同尺度、同高度、同基线、同一白色、米白或珍珠浅灰无缝摄影棚背景，使用相同柔和漫射光与自然软阴影，以留白清晰分隔，无人物、无衣架，四周留白，完整不裁边，黑底仅在明确指定时使用。
```

- 用户明确要求“左背右正”等相反顺序时，按用户指定顺序输出；否则始终左正右背。
- 两栏必须是同一件或同一套服装。款式、配色、材质、图案尺度、包边、系带、珠饰和成套部件保持一致。
- 正面专属结构只出现在正面，背面专属结构只出现在背面；侧缝、肩带、腰线、图案与装饰在前后视图中的连接关系合理。
- 成套服装的正面部件统一放在左栏，背面部件统一放在右栏，不把上装正面与下装背面混在同一栏。
- 默认用留白分栏，不添加“正面、背面”、箭头、编号、尺寸线或其他文字；用户明确要求技术标注时除外。
- `【反向约束】` 至少覆盖：左右顺序颠倒、双正面、双背面、单栏缺失、视图重叠、前后款式不一致、比例不一致、细节错位和裁边。
- “两套方案”是数量要求，不等于“双视图”；只有展示语义明确时才触发本规则。

## 图片反推格式

图片反推通常只有一套，不使用方案总览：

```text
## 识别概览

一句话概括图中有视觉依据的服装组合、配色和风格。

## 穿搭拆解

- 单品层次：按真实穿着顺序列出可见服装、鞋包与少量配饰。
- 轮廓比例：说明长度、松量、腰线和上下装关系。
- 配色图案：说明可见主辅色、图案与落位。
- 面料质感：只写能从图中合理判断的观感，不断言不可见成分。
- 人体依赖单品：仅在图中存在时列出连裤袜、长短袜、鞋、靴、手套等必须脱离隐形肢体展示的单品，并指定空置平铺、轻折或成对独立摆放。
- 不确定项：仅在关键结构被遮挡或模糊时出现。

## 可复制提示词

【主体组合】……
【款式廓形】……
【结构层次】……
【配色图案】……
【面料质感】……
【人体依赖单品】……（仅在图中存在连裤袜、袜子、鞋靴或手套时输出；与主衣物分离，空置平铺、轻折或成对独立摆放，不由隐形腿、脚或手撑起）
【陈列构图】无人物、无衣架；主衣物按层次自然立体陈列，人体依赖单品与裙摆、袖口和裤口留出间距，不连续延伸……
【反向约束】……
```

不要把人物外貌、身份或身材评价混入穿搭拆解。

### 反推中的袜子、鞋与手套

- **连裤袜**：作为一件完整独立单品展示，腰口、裤身、裆部、两条袜腿和袜尖结构可辨；采用空置轻柔平铺或自然折放，不从裙摆向下延伸，不写“裤脚”。
- **长筒袜与短袜**：左右成对、空置平铺或轻折，袜口和袜尖方向清楚；不得形成小腿、脚踝、脚掌和脚趾轮廓。
- **鞋与靴**：成对独立陈列，鞋腔保持自然空置容量，不出现隐形脚、脚背、脚趾或穿着后的腿部连接。
- **手套**：左右成对空置平铺，允许自然手套轮廓，但不得出现皮肤、指甲、掌纹或被隐形手撑开的受力姿态。
- **连接禁令**：这些单品与裙摆、裤口、袖口或身体主体之间必须有可见留白，不得写成“从裙摆向下延伸、从袖口自然伸出、套在隐形腿上”等连续穿着表达。
- 反向约束明确排除：人体、隐形人台肢体、假腿、模特腿、膝盖、小腿肌肉、脚踝、脚掌、脚趾、手掌、皮肤，以及被人体撑起的丝袜、袜子、鞋或手套。
- 输出前检查同一单品术语一致：短袖与七分袖、连裤袜与长筒袜、袜尖与裤脚、裙长和件数不得前后矛盾。

## 可读性检查

输出前确认：

- 总览表能否在不读正文时区分各套方案；
- 各方案字段顺序是否一致；
- 创意概念是否写清母题、形态语言和真正改变服装的创新，而不是空泛风格词；
- 动态字段是否真正对应品类；
- 镜头动态是否写清身材线条、至少两个视角钩子及动态部件轨迹，而不是只写“动感、飘逸”；
- 每个字段是否有新信息，没有换词重复；
- 核心卖点是否能在十几秒内被理解；
- 单独复制任一方案后，主体、结构、材质、展示和反向约束是否完整；
- 展示构图是否默认白色或浅色摄影棚，并排除黑底、强光晕、塑料感、僵硬空壳和无重力漂浮；
- Markdown 表格、标题和空行是否能正常渲染。
